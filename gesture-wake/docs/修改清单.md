  1. **跟随 Flyme 自己的开关**：`mz_quick_wakeup_double_click` → IC 双击模式；`raisewakeup_switch` /

## 6. 开机自愈：fabricated overlay 不跨重启

- 实测（DSU 重启一次后）：`cmd overlay list android` 里 `mzflip_test/mzraise_test` 消失，
  `cmd overlay lookup android android:integer/config_flipSensorType` 又回到 **65538**，
  设置里「抬腕亮屏」开关随之消失。AOSP 的 fabricated overlay 重启后不会被重新注册
  （`.frro` 与 `/data/system/overlays.xml` 里的记录仍在）。
- 因此 `migesture-ksu.zip` 与 `sensortypeoverlay-ksu.zip` 的 `service.sh` 都会在每次开机
  `sys.boot_completed=1` 之后重新执行 `fabricate + enable`（幂等、最多 30 次 × 2s 重试），
  再 `am force-stop com.android.settings` 让设置重读资源 —— **装任一模块即可自愈**。
- 永久方案（不依赖模块 / root）：把 `SensorTypesOverlay-signed.apk` 放进 ROM 的 `product/overlay/`。
- 「双击亮屏」不在这个链条上：它的可见性由 `android:bool/config_automatic_brightness_available`（本机 true）决定，
  恒可见，请到 **设置 → 显示与亮度** 查看。

## 7. 未做 / 已知限制

- **翻转亮屏**未做：本机没有 `flip_status` 传感器，只有 `screen_down(33171037)`，它注册即上报 `1.0`，
  映射给 Flyme 会被当成"翻到正面"立即亮屏，危险。
- **RRO 的 KernelSU 模块形式在这台机器无效**：`/product/overlay` 本身是 overlayfs 挂载点
  （`lowerdir=/mnt/vendor/mi_ext/product/overlay/:/product/overlay`），挂上去会被遮住；请走 ROM 或方式 C。
- **DSU 下不要自行 `adb reboot`**：会退回主系统；KernelSU 模块装完先在 `modules_update/`，下次进 DSU 才生效。
