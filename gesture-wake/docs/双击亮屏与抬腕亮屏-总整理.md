## 0. 现状（全部真机实测）

| 功能 / 开关 | 状态 | 一句话机制 | 关键证据 |
|---|---|---|---|
| **双击亮屏** | ✅ 可用 | 桥下发小米触摸 HAL `ITouchFeature.setModeValue(0,14,1)`（驱动里 mode 14 = `Touch_Doubletap_Mode`），IC 才会进双击模式并把双击上报成 `KEY_WAKEUP(143)` | `dmesg: Touch_Doubletap_Mode value [1]/[0]` 跟随开关；熄屏双击点亮 |
| **抬腕亮屏** | ✅ 可用 | 桥订阅小米 `xiaomi.sensor.pickup(33171036)`，熄屏收到 `1.0`（拿起）→ `PowerManager.wakeUp()`；`2.0`（放下）忽略 | `pickup event value=1.0 screenOn=false power=true` → `wakeUp(time,reason) ok` |
| **开关能控功能** | ✅ 可用 | 桥跟随 Flyme 自己的三个 key：`mz_quick_wakeup_double_click`（双击）、`raisewakeup_switch`/`flipwakeup_switch`（抬手） | 关 → `setModeValue(0,14,0)` + 退订 pickup；开 → 反之 |
| 设置「抬腕亮屏」 | ✅ 可见（依赖覆盖） | 覆盖 `config_flipSensorType`/`config_raiseSensorType` → `MzUtils.supportRaiseFlipFeature()` 变 true | `cmd overlay lookup` = **8 / 8**；UI dump：「抬腕亮屏 开启」 |
| 设置「双击亮屏」 | ✅ 一直可见 | 判断走 `android:bool/config_automatic_brightness_available`（本机解析 **true**），**与上面的覆盖无关** | 显示与亮度 UI dump：「双击亮屏 关闭」（跟随设置值） |
| 翻转亮屏 | ⚪ 未做 | 本机没有 `flip_status`；只有 `screen_down(33171037)`，它**注册即上报 `1.0`**，映射给 Flyme 会被当成"翻到正面"立即亮屏 | — |

## 1. 六个根因（按发现顺序）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 双击不亮屏 | Flyme 只往 `/sys/class/meizu/tp/gesture_control` 写（本机没有这个节点）→ 触摸 IC 从未进入双击模式 | 桥下发 `ITouchFeature.setModeValue(0,14,1)` |
| 2 | 抬腕不亮 + 没开关 | Flyme 依赖魅族私有传感器 **65538/65539**（本机没有）→ 开关被判"不支持"而隐藏、`RaiseFlipperController` 注册 null；而且小米 `pickup` 语义与魅族相反（`1.0=拿起` vs 魅族 `2=拿起`），不能直接复用 | 桥自己订阅 `pickup` 调 `wakeUp()`；用覆盖把两个资源指向 `proximity(8)` 恢复开关 |
| 3 | 开关关掉仍生效 | 初版桥无条件打开 IC 双击模式，没读设置 | 桥跟随上面三个 key（`/system/bin/settings` CLI + 轮询 `settings_system.xml` 的 mtime+size） |
| 4 | 开机后抬手失效（事件收得到但不亮） | KSU `service.sh` 在 **uptime 5.6s** 就起桥，那时 `system_server` 的 power 服务还没注册，`getSystemService(POWER_SERVICE)` 返回 **null 且不自恢复**（`screenOn=false` 是 null 造成的假象；`wakeUp()` 三个出口都没日志才对上） | 桥内 `ensurePower()`（启动等 60s + 每次事件 / 每 10 分钟兜底补取，补到后重读设置）+ `service.sh` 等 `sys.boot_completed=1` |
| 5 | 重启后开关又不见 | **fabricated overlay 不跨重启**（实测：重启后 `overlay list` 里没了、`lookup` 回到 65538/65539） | 两个模块的 `service.sh` 每次开机重建覆盖（幂等 + 重试）；永久方案 = ROM 内静态 RRO |
| 6 | 静态 RRO 的坑 | 这两个资源**不是 public overlayable**，`idmap2 create` 默认拒绝（`no resources were overlaid`） | 命令行加 `--ignore-overlayable`；设备上 OMS 自己给 `/product/overlay` 静态覆盖建 idmap 时不受此限（魅族那个包"命令行失败却照样生效"）；包内已附**预生成 idmap** 兜底 |

## 2. 时间线（含三次自我更正）

1. **静态分析（设备离线）**：双击走魅族 sysfs 节点、抬手走魅族私有传感器 + SensorAux HAL —— 两套接口在这台机器上都不存在；移植只桥接了指纹（FOD）。
2. **真机接入后**：

5. **更正 3（重要）**：我早先写的"运行时覆盖**重启不丢**"是**错的**（那是未经验证的推断）。重启后实测失效（根因 #5）→ 加开机重建，并把文档/README/脚本里的错误说法全部改正 ✅

## 3. 怎么用

### A. ROM 内置（正式、永久、不依赖 root）

| 文件 | 去处 |
|---|---|
| `成品/migesture.jar` | `/system/etc/migesture/migesture.jar` |
| `成品/migesture.rc` | `/system/etc/init/migesture.rc`（照抄 `/system/etc/init/mifod.rc`） |
| `成品/SensorTypesOverlay-signed.apk` | `product/overlay/`（或 `vendor/overlay/`） |

### B. KernelSU 模块（DSU / 临时，推荐）

```sh
adb push 成品/migesture-ksu.zip 成品/sensortypeoverlay-ksu.zip /data/local/tmp/
adb shell su -c 'ksud module install /data/local/tmp/migesture-ksu.zip'
adb shell su -c 'ksud module install /data/local/tmp/sensortypeoverlay-ksu.zip'
# 模块先落 modules_update/，下次进 DSU 生效
```

两个模块的开机脚本都会：等 `sys.boot_completed` → 起桥（supervisor 保活）→ **重建运行时覆盖** → `am force-stop com.android.settings`。
所以"重启后开关又没了"这类问题会**自愈**。

### C. 救急（只对当次开机有效）

```sh
adb shell su -c 'sh 成品/apply_overlay.sh'    # 立刻恢复设置里的抬腕/翻转开关
adb shell su -c 'sh 工具/start_raise.sh'     # 直接打开独立页「抬腕亮屏」（不需要任何覆盖）
```

## 6. 给移植方的坑位备忘

1. **`/product/overlay` 是 overlayfs 挂载点**（`lowerdir=/mnt/vendor/mi_ext/product/overlay/:/product/overlay`，`/mnt/vendor/mi_ext` 只读 erofs）→ KernelSU 模块挂进去的文件会被遮住，静态 RRO 只能进 ROM，或者改用运行时 `cmd overlay fabricate`。
2. **fabricated overlay 不跨重启** → 想留住就得每次开机重建（本项目两个模块都做了），或走静态 RRO。
3. 这两个资源**不是 public overlayable**：命令行 `idmap2 create` 要加 `--ignore-overlayable`，否则 `no resources were overlaid`（魅族自己的包也一样）；但设备上 OMS 会给 `/product/overlay` 的静态覆盖正常生成 idmap（`Constraints: None`），所以放进 ROM 是有效的。
4. 自检 overlay **别用** `Resources.getSystem()` / `systemMain().getSystemContext().getResources()` —— 它们不吃 overlay（永远读到 65538/65539）；要用应用取资源那条路（`getPackageManager().getResourcesForApplication("android")`）。
5. KSU `service.sh` 可能在 `uptime 5s` 就被拉起：那时 `system_server` 的 Java 服务还没注册，`getSystemService()` 会给 null 且不自恢复 → 必须等 `sys.boot_completed`，桥内部还要兜底补取。
6. `app_process` 访问 settings provider 会被 AMS 拒（`Unable to find app for caller`），落盘文件是 ABX 二进制 → 用 `/system/bin/settings` CLI + `settings_system.xml` 的 `mtime+size` 轮询。
7. 启动嵌套 Activity 的类名要带 `$`，并且**从推上去的 `.sh` 里执行**（否则 shell 会把 `$XXX` 吃掉）。
8. **DSU 里不要自己 `adb reboot`**（会退回主系统）；模块装完先落 `modules_update/`，下次进 DSU 才生效。

## 7. 还没做的

| 项 | 说明 |
|---|---|
| **翻转亮屏** | 本机没有 `flip_status`；`screen_down(33171037)` 注册即上报 `1.0`，直接映射会立刻误亮屏 → 需要另找信号，或干脆不做 |
| **静态 RRO 的 ROM 侧最终确认** | 已验到"APK 内容/映射正确 + OMS 会给 `/product/overlay` 静态覆盖建 idmap"；真正装进 ROM 启动一次的效果需在重打包 ROM 时确认（DSU 里不能重启验证这条路） |
| **「双击亮屏选项丢失」的具体位置** | 我 dump 到它在 **显示与亮度** 里（一直可见）；如果你是「息屏显示和锁屏」那页看的，那页在本移植上是禁用的 |
| **「息屏显示和锁屏」页为何被禁用** | 组件在 `dumpsys package` 里存在，但 `am start` 报 does not exist，`pm enable` 无效；需要的话可以继续挖 |
